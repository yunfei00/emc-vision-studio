# 《消失的信号》v0.3 高质量重制：设计、快速验证与验收

> 分支：`feature/v0.3-cinematic-quality`；基于 v0.2 开发分支。v0.1.0 Release 与 v0.2 视频均不覆盖。
> 本轮只做**兼容性验证 + 三镜头真实质量对比**，没有证明 V100S 已兼容 Wan 2.2，更没有声称达到电影级质量。

## 1. 目标与验收标准

- 最终目标：19 镜头、103 秒、稳定的中国工程师形象、可信的射频实验室、自然动作、清晰画面、中文字幕与音效。
- 先测试 S007（脸）、S010（手部连接同轴线）、S016（频谱仪），因为它们最容易暴露模型缺陷。
- 以**模型真实生成的原生连续帧**评价，不允许通过重复末帧、放大到 4K 或强插帧冒充真实动作。
- 最低技术目标：测试输出至少 24fps 的帧序列，理想每镜头 5 秒以上连续运动；720p 为目标分辨率。若模型只输出较短序列，必须在报告中如实显示。
- 人工质量目标：脸型身份一致、双手结构正确、仪器面板不明显漂移、无明显闪烁；3 个镜头都达到“可接受”才能继续。
- 不将硬件通过、脚本退出码 0 当成视觉验收通过。

## 2. 运行路线和硬件判断

V100S 32GB 属于 Volta 架构（通常计算能力 sm70）。它的显存容量足够尝试部分量化或卸载式视频模型，但不原生支持 BF16；很多面向较新 NVIDIA 架构的 FlashAttention、Triton 和 FP8 工作流不能直接在 V100S 上运行。**不要仅因为模型宣称 24GB 显存就认定能运行。**

候选路线：
1. 优先尝试 **Wan 2.2 TI2V-5B** 的图生视频工作流（确认其真实 I2V 输入和依赖），测试 FP16 与兼容的 PyTorch attention 路径；禁用必须依赖 sm80+ 的加速算子。
2. 如果工作流不兼容 sm70，记录报错并停止，不反复下载同一模型；评估兼容的旧版本/其他模型或云 GPU。
3. 如果能运行但三镜头仍变形，则瓶颈是模型与控制策略，不是单纯显存；再评估角色参考、分层合成、专用动作控制与高质量后期。
4. 只有三个镜头通过，才允许扩展 19 镜头；全片按镜头逐个验收、替换失败镜头。

**重要：** 本仓库不自动下载几十 GB 模型、不自动升级 torch、不覆盖 SafeMode 节点。必须先确认具体的官方 ComfyUI 工作流与本机版本匹配，才执行推理。

## 4. 模型准备（仅当硬件检查后确认兼容）

通过 ComfyUI 的实际工作流完成模型部署。需要导出 **API 格式** JSON，不能使用默认 UI 工作流 JSON。工作流必须包含：
- 一个明确的 `LoadImage` 节点，输入静态关键帧；
- Wan 图生视频所需模型、VAE、文本编码器、采样节点；
- 一个 `SaveImage` 节点，输出连续视频帧。

在 ComfyUI 启用开发者选项后，使用 **Save (API Format)** 导出为本机私有文件：
`D:\AI-Video\private\lost-signal\v0.3\wan_i2v_api.json`

确认工作流节点 ID：`LoadImage` 的数字 ID 和 `SaveImage` 的数字 ID。**不能把普通 UI JSON 当作 API JSON，也不能把 SaveVideo 节点误当 SaveImage。**

优先测试单个镜头 S007 的手动工作流是否能运行；如果它报 `no kernel image available`、`unsupported bf16`、`flash_attn`、`triton` 等错误，属于兼容性问题，不要靠反复重跑解决。

## 5. 三镜头一键质量测试

工作流能够成功手动运行、且确认 `LoadImage` 与 `SaveImage` ID 后，运行（将 **12、47 替换为真实节点 ID**）：

```powershell
uv run python scripts/v03_benchmark.py --workflow "D:\AI-Video\private\lost-signal\v0.3\wan_i2v_api.json" --image-node 12 --save-node 47
```

脚本自动替换 S007、S010、S016 输入图，分别向 ComfyUI 提交任务，保存原始连续帧、原生 24fps MP4 和基准报告。**不会拉长镜头或补末帧**。

输出：
- `D:\AI-Video\private\lost-signal\v0.3\pilot\S007\S007_native.mp4`
- `...\S010\S010_native.mp4`
- `...\S016\S016_native.mp4`
- `...\pilot\benchmark_report.json`

报告包含真实帧数、实际时长、分辨率、生成耗时。请注意：脚本以 24fps 封装帧序列；如果工作流实际采用其他原生 FPS，应在工作流中设置为 24fps，否则该报告仅代表 24fps 封装结果。

**已知约束：** 自动化脚本不能自动识别复杂视频模型是否输出了正确动作、是否扭曲面部或手指。三个 MP4 必须人工对比 v0.2。

## 6. 一次反馈就能决策

运行完提供两个 JSON 的内容或终端报错：
- `v0.3\reports\hardware_preflight.json`
- `v0.3\pilot\benchmark_report.json`

人工观看三段后反馈：S007 脸部合格/不合格；S010 手部合格/不合格；S016 仪器合格/不合格。然后一次决定：
- **全部合格、运行成本可接受**：进入 19 镜头高质量重制与专业后期。
- **能运行但变形**：调整动作控制与参考素材，针对失败镜头迭代；不全片重算。
- **V100S 不兼容或耗时不可接受**：停止本地大规模推理，选择更合适模型或云端算力，不盲目升级显卡。

## 7. v0.2 字幕问题单独处理

v0.2 生成的有声无字幕问题，与 V100S 视频推理能力无关。检查 `v0.2\delivery\final_report.json` 的 `subtitles` 字段和源 SRT；若为 `disabled`，说明运行过 `--no-subtitles`；若为 `burned` 但画面无字，需要检查 FFmpeg 实际渲染输出及字幕时间轴。**不要用 v0.3 模型验证掩盖 v0.2 的字幕缺陷。**

## 8. 后续完整制作阶段（通过验证后才执行）

P1 静态素材升级与角色设定锁定 → P2 三镜头真实视频测试 → P3 19 镜头逐镜头生成与质量评分 → P4 镜头替换、去闪烁、色彩匹配 → P5 字幕与中文配音、音效及音乐混音 → P6 103 秒母版、交付报告与人工最终验收。

验收失败时只返工失败镜头；保留输入图、工作流、随机种子、模型版本、GPU 耗时与质量报告。全部私有媒体只存本地，GitHub 仅存代码与文档。

## 9. 模型逐个淘汰测试（V100S 单卡优先）

测试顺序：① Wan 2.2 TI2V-5B → ② Wan 2.1 I2V-14B（需适当量化/卸载）→ ③ LTX-Video 2B。顺序是探索性建议，不保证每款能在 Volta sm70 运行。禁止一次性下载三个模型。

**统一测试纪律：**
1. 先执行第 3 节硬件预检，核对 ComfyUI 环境与模型实际精度；先做一张图的 S007，不能运行则停止该模型并记录报错。
2. 第一镜头通过后，再生成 S010、S016；用第 5 节 `v03_benchmark.py` 保存原生帧和 MP4。不要用重复末帧补时长。
3. 每款模型保持相同三张输入关键帧、尽可能接近的动作描述、固定随机种子与目标时长，记录模型权重文件名、版本、推理参数、分辨率、帧数、GPU 峰值显存和实际耗时。不同模型的采样参数不必强行相同。
4. S007 评价人脸、五官、人物一致性；S010 评价手指、手臂和接线动作；S016 评价频谱仪结构、波形及闪烁。
5. 评分权重：结构正确 30、动作连续自然 25、清晰真实 20、一致性 15、稳定性和速度 10。每项按权重范围给分；总分≥80 且无严重形变，才考虑采用。
6. 若出现 sm70 不兼容、BF16/FP8/FlashAttention 算子错误、显存不足或过慢，记录原因后进入下一候选；不要通过修改生产环境盲目重试。
7. **选择标准**：先看质量和真实连续运动，再看耗时。三镜头合格后才开始 19 镜头生产。

**最低反馈资料**：`hardware_preflight.json`、`benchmark_report.json`、三个原生视频的人工评分；若模型启动失败则提供终端最后 100 行错误日志。不要上传私人原始素材到公开 GitHub。

注意：`v03_benchmark.py` 是针对导出 API 格式、使用 `LoadImage` 和 `SaveImage` 节点的工作流。对于直接输出视频文件而非图片帧的工作流，需要另写适配器，不能假设现有脚本支持所有模型工作流。

## 11. 已下载三个模型后的 S007 首次生成：电脑逐步操作（2026-10-13）

**当前进度**：V100S 32GB、PyTorch 2.7.0+cu126、ComfyUI 普通模式网页可打开；用户已下载 Wan 2.2 三个文件。此处只做 S007 短片兼容性测试，不代表最终画质验收。

### 步骤 1：在 PowerShell 检查三个文件

```powershell
$base = "D:\AI-Video\ComfyUI\models"
@(
  "$base\diffusion_models\wan2.2_ti2v_5B_fp16.safetensors"
  "$base\text_encoders\umt5_xxl_fp8_e4m3fn_scaled.safetensors"
  "$base\vae\wan2.2_vae.safetensors"
) | ForEach-Object {
  if (Test-Path $_) {
    Get-Item $_ | Select-Object Name, @{Name="GB";Expression={[math]::Round($_.Length/1GB,2)}}
  } else {
    Write-Host "MISSING: $_"
  }
}
```

三个文件必须存在且不是异常的小文件。若有 MISSING，按第 10 节对应路径移动文件。

### 步骤 2：普通模式启动 ComfyUI

关闭已有 ComfyUI 进程，进入仓库根目录运行：

```powershell
cd D:\AI-Video
.\scripts\start_windows_v100.ps1 -Root "D:\AI-Video"
```

不要加 `-SafeMode`；该模式会强制 FP32 并禁用自定义节点。浏览器打开 http://127.0.0.1:8188 。

### 步骤 3：下载并导入官方工作流

浏览器打开：[ComfyUI 官方 Wan 2.2 TI2V-5B 工作流 JSON](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/video_wan2_2_5B_ti2v.json)。

在 GitHub 文件页点击 **Raw / Download raw file** 保存 JSON；在 ComfyUI 页面将 JSON 拖入画布。若该链接不存在或工作流节点缺失，停止并反馈，不要自行乱装不明节点。

在工作流的模型选择框里选择：
- diffusion model：`wan2.2_ti2v_5B_fp16.safetensors`
- text encoder：`umt5_xxl_fp8_e4m3fn_scaled.safetensors`
- VAE：`wan2.2_vae.safetensors`

如果下拉框看不到文件，确认放置路径后重启 ComfyUI。

### 步骤 4：S007 最小兼容性测试

将本项目 S007 的人物关键帧上传到工作流的 **图生视频输入**；不要使用纯文生视频分支。具体关键帧路径以 `D:\AI-Video\private\lost-signal\v0.2\manifest.json` 中 S007 的 filename 为准，对应 `v0.2\keyframes\` 文件夹。

在工作流允许调整的地方，先设置：**宽 512、高 288、49 帧、12～16 采样步**。如果官方工作流要求分辨率是 16 的倍数，512×288 符合要求；若节点限定其他尺寸，以节点提示为准。不要修改模型精度或替换为 SVD。

点击 **Queue Prompt / Run**，等待生成。49 帧按 24fps 约 2.04 秒，仅用于验证能否跑通；最终质量测试要另用更高分辨率和更长序列。

### 步骤 5：验收与反馈

- **成功**：确认输出视频能够播放，观察人脸、五官、手指、动作是否变形，记录耗时与峰值显存。
- **失败**：保留 ComfyUI 终端最后 20～30 行报错，特别是 `out of memory`、`BF16/FP8`、`flash attention`、`no kernel image` 等。
- **模型文件加载失败**：先检查模型选择框与文件名，不要随意升级 torch。
- **生成质量一般**：这只是短片兼容性测试；先确保成功运行，再升级到完整 S007 质量测试。

将结果反馈为「S007 成功/失败 + 耗时 + 错误末尾文字或画面问题」，下一步再决定是否进行 S010/S016。**不需要复制长 JSON。**
