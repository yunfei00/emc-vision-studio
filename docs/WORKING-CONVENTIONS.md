# 项目协作与操作记录规范

> 生效日期：2026-10-09

## 唯一操作说明来源

**后续所有需要用户复制、执行、检查的操作，必须先写入 GitHub 仓库文档。** 聊天中只提供 GitHub 文件链接、简短摘要和实际提交 SHA，不要求用户从聊天中复制长命令。

## 每次任务必须记录

1. 本次目标与适用环境（Windows 10、Tesla V100 32GB 显存、128GB 内存、2TB 硬盘）。
2. 前置条件和精确的 PowerShell 命令或可直接运行的脚本。
3. 预期输出、成功判断标准和常见错误处理。
4. 自动化验证与实际运行结果；未运行必须明确写“未验证”。
5. 本次修改文件、提交 SHA、下一步计划。
6. 视频生产需额外记录模型/许可、工作流、提示词、种子、素材与成品路径、验收结果。

## 文档位置

- `docs/operations/`：逐次操作手册，命名 `YYYY-MM-DD-主题.md`。
- `docs/progress.md`：项目阶段状态和提交记录。
- `docs/environment/`：安装环境、硬件与故障排查。
- `docs/acceptance/`：每阶段验收。
- `productions/001-lost-signal/`：剧本、分镜、提示词、镜头、媒体及 QA。
- `scripts/`：能自动化的操作优先交付脚本，文档指向脚本。

## 执行原则

- 优先自行完成 GitHub 更新、脚本检查和可自动化的验收；只在确实需要访问用户本地 Windows 机器时请求用户运行。
- 用户已确认的硬件信息不重复索取。
- 禁止将计划描述为已安装或已验收；记录真实结果。
- GitHub 为 Public，素材可以按项目约定提交，媒体使用 Git LFS；账号密码、令牌等秘密仍不得提交。
- 每次 GitHub 修改完成后，聊天中给出**文档直达链接**和提交记录。
