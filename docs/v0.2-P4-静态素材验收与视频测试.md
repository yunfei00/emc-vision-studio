打开 PowerShell，先切换到**你自己的仓库根目录**（不要把私有素材目录当成仓库）：


预期分支：`feature/v0.2-quality-upgrade`。如果 `git status` 显示本地改动，或 `git pull` 因冲突失败，**先停止，不要 reset、clean 或强制覆盖**。本地 `pyproject.toml` 如有自定义配置，先备份并核对差异。

## 4. P4.3 三镜头生成与画质验收（脚本已提交）

**首次测试：** 先启动 ComfyUI SafeMode，在仓库根目录执行：

```powershell
git pull --ff-only origin feature/v0.2-quality-upgrade
uv run python scripts/v02_p4_render.py --mode pilot --engine svd-test
```

将独立生成 S007、S010、S016 的低运动 SVD 测试片段。每段使用固定 seed、14 帧、6fps、motion_bucket=28，随后转换到分镜目标时长（6、6、5 秒）。生成失败会回退到原图缓慢推镜。**回退代表有视频文件，不代表 AI 画质合格。**

输出位置：
- `D:\AI-Video\private\lost-signal\v0.2\p4\pilot\S007\S007.mp4`
- `D:\AI-Video\private\lost-signal\v0.2\p4\pilot\S010\S010.mp4`
- `D:\AI-Video\private\lost-signal\v0.2\p4\pilot\S016\S016.mp4`
- `D:\AI-Video\private\lost-signal\v0.2\p4\pilot\render_report.json`

检查报告中每个镜头的 `method`：`svd` 表示 SVD 生成；`safe_fallback` 表示模型失败，采用静态图缓推。

**如果 SVD 人物或仪器发生变形，直接生成稳定版对比：**

```powershell
uv run python scripts/v02_p4_render.py --mode pilot --engine safe
```

注意：上述命令会替换 `pilot\Sxxx\Sxxx.mp4`，但不会覆盖原始图片；如需保留 AI 版本，先自行复制三个 MP4 到另一私有目录。

人工验收要点：S007 脸型与服装；S010 手指、手臂和同轴接头；S016 频谱仪图形及读数稳定；同时检查清晰度、闪烁和异常运动。脚本只能验证视频是否成功输出及其时长，不能自动判定人物结构正确。

## 5. P4.4 全 19 镜头生成（仅在三镜头画质确认后）

**推荐稳妥混合方案：** 人物、手部和仪器敏感镜头使用原图缓推；其余镜头尝试低运动 SVD，模型失败自动回退。按权威 storyboard 顺序生成全部 19 段，目标总时长 103 秒。

```powershell
uv run python scripts/v02_p4_render.py --mode all --engine hybrid --accept-pilot
```

如果希望全部使用无形变的原图缓推方案：

```powershell
uv run python scripts/v02_p4_render.py --mode all --engine safe --accept-pilot
```

输出：`D:\AI-Video\private\lost-signal\v0.2\p4\full\Sxxx\Sxxx.mp4`，以及 `full\render_report.json`。

`--accept-pilot` 代表你已经亲自检查三镜头的画质；不能仅凭 `P4.2 READY` 就使用此参数。19 段生成完毕后仍须逐段验收，**尚未自动合成为 103 秒成片**。

## 6. 故障与反馈

- `P4.1 FAIL`：检查文件名、时间线、重复图片、解码错误；不要用其他图片顶替。
- `P4.2 NOT_READY`：按终端 `CHECK:` 定位缺失模型、节点、服务或工具。
- `SVD failed, safe fallback`：检查 `render_report.json` 的 `warnings`；可以先采用稳定版，或复制具体报错排查模型。
- 视频变形：使用 `--engine safe` 对比，不要调高 motion_bucket 或无限续接。
- 反馈方式：复制 PowerShell 输出或报告中的错误文字；无需截图、无需 Codex。
