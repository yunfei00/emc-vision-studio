将独立生成 S007、S010、S016 的低运动 SVD 测试片段。每段使用固定 seed、14 帧、6fps、motion_bucket=28，随后转换到分镜目标时长（6、6、5 秒）。生成失败会回退到原图缓慢推镜。**回退代表有视频文件，不代表 AI 画质合格。**

输出位置：
- `D:\AI-Video\private\lost-signal\v0.2\p4\pilot\S007\S007.mp4`
- `D:\AI-Video\private\lost-signal\v0.2\p4\pilot\S010\S010.mp4`

- `D:\AI-Video\private\lost-signal\v0.2\p4\pilot\render_report.json`

检查报告中每个镜头的 `method`：`svd` 表示 SVD 生成；`safe_fallback` 表示模型失败，采用静态图缓推。

**如果 SVD 人物或仪器发生变形，直接生成稳定版对比：**

## 6. 故障与反馈

- `P4.1 FAIL`：检查文件名、时间线、重复图片、解码错误；不要用其他图片顶替。
- `P4.2 NOT_READY`：按终端 `CHECK:` 定位缺失模型、节点、服务或工具。
- `SVD failed, safe fallback`：检查 `render_report.json` 的 `warnings`；可以先采用稳定版，或复制具体报错排查模型。
- 视频变形：使用 `--engine safe` 对比，不要调高 motion_bucket 或无限续接。
- 反馈方式：复制 PowerShell 输出或报告中的错误文字；无需截图、无需 Codex。

## 8. P4.6 生成 v0.2 最终 103 秒成片

用户已确认 11 个修复镜头画质合格（A）。直接从现有视频合成，不再运行 ComfyUI，不重算 SVD。

在**仓库根目录**执行：

```powershell
git checkout feature/v0.2-quality-upgrade
git pull --ff-only origin feature/v0.2-quality-upgrade
uv run python scripts/v02_p4_finalize.py
```

脚本会：
1. 依照 `plans/phase8_lost_signal_storyboard.json` 的**实际分镜顺序**检查 19 段、103 秒；
2. 从 `p4\repair_dynamic\` 取 S007、S009～S018 共 11 段，从 `p4\full\` 取其余 8 段；
3. 统一编码为 1280×720、24fps，再无缝拼接；
4. 复用 `private\lost-signal\phase10\lost_signal_phase10_voiced.mp4` 中已完成的中文配音和音乐音轨；
5. 使用 `private\lost-signal\phase10\lost_signal_zh.srt` 烧录中文字幕；
6. 验证音视频轨和最终时长，只有验证通过才替换目标输出。

最终成片：
`D:\AI-Video\private\lost-signal\v0.2\delivery\lost_signal_v0.2_final_103s.mp4`

技术报告：
`D:\AI-Video\private\lost-signal\v0.2\delivery\final_report.json`

**说明：** 脚本复用原来的音频，不会重写 v0.1 的文件。视频合成后须人工播放确认字幕、配音和镜头切换。若原音频或 SRT 不在上述位置，程序会明确报缺失，不会静默生成无声片。

如果 FFmpeg 报 `No such filter: subtitles` 或 libass 相关错误，可先用以下命令生成**不烧字幕**的音画版本：

```powershell
uv run python scripts/v02_p4_finalize.py --no-subtitles
```

此参数会生成同名文件且**不含字幕**，仅用于诊断或应急；要交付有字幕的版本，仍应修复 FFmpeg 字幕滤镜后重新运行默认命令。

若最终合成中途失败，检查终端最后的错误内容；原有 `p4\full\`、`p4\repair_dynamic\`、v0.1 音频和 v0.1 发布版不会被修改。合成脚本仅在本地运行，不会把私有素材提交 GitHub。
