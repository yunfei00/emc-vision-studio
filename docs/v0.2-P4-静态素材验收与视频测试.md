# v0.2-P4 静态素材验收与三镜头测试

## 约束
仅 feature/v0.2-quality-upgrade；不修改 v0.1.0、原视频或 P2 输出。私有素材、manifest、报告与视频全部保存在 D:/AI-Video/private/lost-signal/v0.2，不上传 GitHub。禁止无限末帧续接。

## 前置验收（阻断条件）
1. 读取本地 manifest.json，核实每个镜头 S001–S019 恰好一条映射；检查相对路径不得越过私有素材根目录，禁止自动采用文件名猜测来修复歧义。
2. 按 plans/phase8_lost_signal_storyboard.json 中 acts/shots 的实际顺序检查，时长总和应为 103 秒；切勿按镜头编号排序。
3. 对每张图验证可解码、分辨率、宽高比、SHA256；对两张人物参考图执行同样检查。
4. 按 SHA256 检查重复内容；尤其 S009 与 S018 不得引用相同路径或相同哈希。必要时人工检查视觉近重复，哈希不同不代表视觉内容不同。
5. 任何缺失、损坏、映射冲突都应中止生成，输出本地 JSON 报告；禁止自动以其他镜头替换。

## 首轮三镜头
- S007：人物面部与服装一致性，尽量低运动；
- S010：连接同轴线，避免大幅手指/手腕变化；
- S011：仪器特写，测试 SVD 或 FFmpeg 稳定缓推。

## 工作流
1. 先运行环境检查：nvidia-smi、ComfyUI /object_info、已安装模型清单、ffmpeg/ffprobe。不得未经验证更换 SafeMode 或自动下载模型。
2. 使用已验收的 P3 图片作为唯一输入；SVD 初始候选仅短片段、低 motion_bucket、固定 seed，保留原帧；人物镜头如果变形，回退 FFmpeg 静态图缓推，不强行通过。
3. 输出候选到 private/lost-signal/v0.2/p4/candidates/S007、S010、S011；记录模型、节点、参数、seed、输入 SHA256、输出文件和时长。
4. 逐镜头人工验收：脸部与参考图一致，手指/手臂连续，无明显模糊、闪烁、重复帧及不自然动作。自动指标只用于筛查，不能自动证明结构正确。
5. 首轮三镜头全部验收后，再规划剩余镜头；未经验收禁止运行全部 19 镜头。

## 安全
提交前运行 git status --short 与 git diff --cached --name-only，确保无 private/、PNG、MP4、音频、模型、原始报告。只允许提交代码与去敏文档。所有本地脚本先运行 py_compile 和 --help/静态测试，失败即停止。
